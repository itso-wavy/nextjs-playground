# Next.js App Router 설정 가이드

이 문서는 기존의 Pages Router 프로젝트에 App Router 구조를 추가하는 과정을 설명합니다.

## 설정 과정

### 1. 디렉터리 구조 생성(https://nextjs.org/docs/app/getting-started/installation#create-the-app-directory)

먼저 App Router에 필요한 디렉터리 구조를 생성합니다:

```bash
mkdir -p app/api/hello
```

### 2. 루트 레이아웃 생성 (`app/layout.tsx`)

App Router의 핵심인 루트 레이아웃을 생성합니다:

```tsx
import type { Metadata } from 'next';
import { Geist, Geist_Mono } from 'next/font/google';
import './globals.css';

const geistSans = Geist({
  variable: '--font-geist-sans',
  subsets: ['latin'],
});

const geistMono = Geist_Mono({
  variable: '--font-geist-mono',
  subsets: ['latin'],
});

export const metadata: Metadata = {
  title: 'Create Next App',
  description: 'Generated by create next app',
};

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang='en'>
      <body
        className={`${geistSans.variable} ${geistMono.variable} antialiased`}
      >
        {children}
      </body>
    </html>
  );
}
```

**주요 특징:**

- `Metadata` 타입을 사용한 메타데이터 관리
- 폰트 설정을 레이아웃에서 직접 처리
- `children`을 통해 페이지 컨텐츠 렌더링

### 3. 홈페이지 생성 (`app/page.tsx`)

App Router의 홈페이지를 생성합니다:

```tsx
import Image from 'next/image';
import styles from './page.module.css';

export default function Home() {
  return (
    <div className={styles.page}>
      <main className={styles.main}>
        <Image
          className={styles.logo}
          src='/next.svg'
          alt='Next.js logo'
          width={180}
          height={38}
          priority
        />
        <ol>
          <li>
            Get started by editing <code>app/page.tsx</code>.
          </li>
          <li>Save and see your changes instantly.</li>
        </ol>
        {/* ... 나머지 컨텐츠 */}
      </main>
    </div>
  );
}
```

**변경사항:**

- Pages Router에서는 `pages/index.tsx`였지만, App Router에서는 `app/page.tsx`
- 스타일 파일 경로가 `./page.module.css`로 변경

### 4. 글로벌 스타일 설정 (`app/globals.css`)

기존 `styles/globals.css`의 내용을 `app/globals.css`로 복사:

```css
:root {
  --background: #ffffff;
  --foreground: #171717;
}

@media (prefers-color-scheme: dark) {
  :root {
    --background: #0a0a0a;
    --foreground: #ededed;
  }
}

/* ... 나머지 스타일 */
```

### 5. 페이지 스타일 설정 (`app/page.module.css`)

기존 `styles/Home.module.css`의 내용을 `app/page.module.css`로 복사하여 App Router 페이지에서 사용할 수 있도록 설정.

### 6. API 라우트 생성 (`app/api/hello/route.ts`)

App Router의 새로운 API 라우트 형식으로 변환:

```tsx
import { NextResponse } from 'next/server';

export async function GET() {
  return NextResponse.json({ name: 'John Doe' });
}
```

**Pages Router vs App Router API 차이점:**

**Pages Router** (`pages/api/hello.ts`):

```tsx
import type { NextApiRequest, NextApiResponse } from 'next';

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<Data>
) {
  res.status(200).json({ name: 'John Doe' });
}
```

**App Router** (`app/api/hello/route.ts`):

```tsx
import { NextResponse } from 'next/server';

export async function GET() {
  return NextResponse.json({ name: 'John Doe' });
}
```

### 7. CLAUDE.md 업데이트

프로젝트 가이드를 App Router 구조에 맞게 업데이트했습니다.

## App Router vs Pages Router 비교

### 파일 구조

| 기능       | Pages Router         | App Router               |
| ---------- | -------------------- | ------------------------ |
| 홈페이지   | `pages/index.tsx`    | `app/page.tsx`           |
| 레이아웃   | `pages/_app.tsx`     | `app/layout.tsx`         |
| API 라우트 | `pages/api/hello.ts` | `app/api/hello/route.ts` |
| 글로벌 CSS | `styles/globals.css` | `app/globals.css`        |

### 주요 차이점

1. **메타데이터 관리**: App Router에서는 `Metadata` 타입과 `export const metadata`를 사용
2. **API 라우트**: HTTP 메서드별로 명명된 함수 사용 (GET, POST 등)
3. **레이아웃**: 더 직관적인 레이아웃 시스템
4. **폰트 최적화**: 레이아웃에서 직접 폰트 설정

## 호환성

- 두 라우터 시스템이 동시에 존재할 수 있습니다
- 기존 Pages Router 파일들은 여전히 작동합니다
- 새로운 개발은 App Router 사용을 권장합니다

## 실행 방법

설정 완료 후 개발 서버를 실행:

```bash
pnpm dev
```

http://localhost:3000 에서 App Router 기반 애플리케이션을 확인할 수 있습니다.
